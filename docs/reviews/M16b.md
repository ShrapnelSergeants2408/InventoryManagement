## Details I filled in (confirmed by Dan, 2026-10-28; SPEC v0.11)

These follow from §18 but the spec doesn't spell them out:

- **(a) `counts.csv` `on_hand` blank = not counted.** A row for an item whose barcode or location changed without a count has blank `on_hand` and `counted_at`. M16c will read it that way.
- **(b) A helper can't set an item back to "No location".** A blank location in the file means "unchanged" (§18.4), so the helper's picker doesn't offer No location.
- **(c) Progress on a helper starts at 0.** The kit's items arrive "not counted yet" on the helper, so "counted" means counted on this device. The shop tablet's own counts come back unchanged with the import.
- **(d) "Outside the assignment" is decided by the item as the kit gave it.** Moving an item into an assigned location doesn't make it "inside".
- **(e) A barcode already on an item can't be given to a new item** on the helper ("Count that item instead"). The shop tablet still flags likely duplicates between pending items (§18.5).
- **(f) "n changes"** counts each item, new location and new item changed since the last send once, however many times it was changed.
- **(g) The helper's Add item form is its own, smaller form**, not the shop tablet's editor: no spares, no second or third vendor, no PIN. The plan called the Add item form a shared component. A separate form was simpler and leaves the tablet's editor exactly as it was (pixel-identical above).

## Notes

1. **Not built here (by the plan):** Import counts, conflicts, Undo, pending review on the shop tablet: M16c. Until then a counts file can be made but not imported.
2. **The helper copy has no price**, so the helper's Add form lets a student type a price for a new item (§18.3 allows it). Existing items' prices are never shown.
3. **Count options and the pause** are kept in the browser (as on the shop tablet). Opening a kit sets the mode to the kit's kind and clears the pause.
4. **"Count with several devices" is still a shop-tablet feature only.** A helper can't make kits.
5. **Old browsers without `indexedDB.databases()`** (Safari before 14, Chrome before 71) fall back to `Dexie.exists`, which opens a database only if it exists and creates nothing. The Tab S8 and current phones have `databases()`. If the browser can't say at all, the device is treated as the shop tablet, as every device was before this milestone.

8. Count one more item, then **Leave helper mode**: it should ask to send first. Choose **Discard and leave**: the question comes back.

**On an iPhone (Safari), if one is handy:** steps 3–8, especially that **Scan reads a QR label** (the zxing stand-in) and that **Send** opens the iOS share sheet with the ZIP.

9. Say whether the 360 px layout looks right on a small phone, and anything that's awkward to use with gloves.
