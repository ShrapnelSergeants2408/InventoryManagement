## Details I filled in (for Dan to confirm)

- (a) **A device id is per opened kit, not per phone.** A phone that opens a kit a second time (after Leave helper mode, or after losing its data) gets a new id, so the warning reads "opened on 2 devices, or opened again on one". The app keeps nothing on a phone between kits that could identify it.
- (b) **Two devices on one kit give a warning, not conflicts.** Their counts still apply as one helper's: the newest count of an item is used without asking, as in 1.0.0. Making them conflicts would need the tablet to store a device with every item's count. The warning says to check that two people didn't count the same items.
- (c) **The format version of the counts file stays 1.** The new field is extra, and the new item ids keep the old shape (`pending-<helper id>-<number>`), so a tablet still on 1.0.0 can import a 1.1.0 phone's file and the other way round. A tablet on 1.0.0 doesn't warn.
- (d) **Item numbers:** a random six-digit block per opened kit, 10,000 numbers each. Two openings share a block about once in 900,000 pairs; a helper would need over 9,999 new items from one kit to run into the next block.
- (e) **"I've sent it" is the student's word.** The app can't see whether the file reached Drive or the tablet. The notice stays until that tap or the next send.
- (f) **A kit saved to Downloads is still recorded as sent** on the helper's card ("Last kit sent …", name locked), as in 1.0.0. Only the dialog says it hasn't reached the helper.
- (g) **The QR card sits above the helper cards** (below "No helpers yet" on an empty screen) and is always shown. The code holds the address this copy of the app runs at, so it's right for the live site and for a test copy.
- (h) **Wording** of the new notices, the warning and the QR card, as in the screenshots and SPEC §18.1, §18.4, §18.5.

## Tablet check (for Dan, after merging)

Nothing here adds records to the real inventory except one test helper, removed in step 9. Counts are previewed and not applied.

1. **Back up first:** More › Backup, restore & price import › Full backup (ZIP).
2. **Update the tablet:** swipe the app away, Android Settings › Apps › Chrome › Force stop, open the app for about 15 seconds, then reopen it (or open the site in a Chrome tab and refresh). More › About should read **1.1.0**. Don't clear site data.
3. Count › Helper devices: the **Open the app on a helper** card shows a QR code and `team2408.com/InventoryManagement/`.
4. Scan the code with a phone's camera. The app opens in the phone's browser and asks **What is this device?** (A phone that already joined shows its helper screen; reload it once so it has 1.1.0.)
5. On the tablet, add a helper "M24 test" with one category and **Send count kit**. Expect "Saved to Downloads, not sent yet" with the file's name. Tap **Done**, then get the file to the phone (Drive).
6. On the phone: Join as a helper with that kit, count one item, then Send › **Send my counts**.
   - Android: expect "Saved to Downloads", "Not on the shop tablet yet" and a "!" on the Send tab. Upload the file to Drive, tap **I've sent it**: it changes to "Last sent" and "Everything is sent".
   - iPhone: the share menu opens, and afterwards it reads "Last sent" straight away.
7. On the tablet: Count › Import counts, choose the file. The preview shows 1 count and no warning. **Don't apply:** leave with the back button.
8. On the phone: Send › Leave helper mode.
9. On the tablet: Count › Helper devices › **Remove** "M24 test".

Say what step 5 and step 6 showed on your devices; those are the two things this build assumes about Chrome on Android.
