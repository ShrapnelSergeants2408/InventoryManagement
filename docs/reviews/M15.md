## Decisions made while building (for Dan)

1. **+/− on a line changes one whole pack**, and stops at one pack (Remove takes the line off). A quantity is stored in the item's unit (§3), so a list made "up to desired" in M15b can hold 7 of a 5-pack. That shows as 2 packs, and + makes it 15.
2. **The Add dialog remembers the list used last** (until the app is reloaded), so adding several items to one list is two taps each.
3. **The item row's ⋮ menu** holds Add to order list, Open details and Print QR label. It's a new 56 px column at the end of the row (beside the chip in portrait).
4. **Remove a line asks first** (gloves); +/− don't.
5. **The count-in banner shows only on the Automatic list.** Named lists keep the stale-price banner and flags.

## Findings

1. **The plan's rollback step couldn't work as written.** Plan §3 step 3 expected the old build to show the guard screen. The guard is new in M15, so no older build has it. The step now shows what a rollback actually does: today's build opens the v2 database and leaves the v2 data alone. The guard itself is tested from v2 against a database marked v3. Corrected in `docs/stage6-plan.md`. So the guard protects against rollbacks from M15 onward, not to builds before it. On today's evidence, rolling back to the M14 build is harmless.
2. **Fixed while testing: one test let a mutant through.** Removing the app's own duplicate-name check survived, because the database's unique index also refuses the name, and its message ("Key already exists…") matched the test's `/already/`. Both layers work; the test now expects the app's own message.
3. **Fixed while building: an apostrophe.** The duplicate-name message used ' where the app's other messages use ’. Caught by the browser check.
4. **Earlier checks updated for intended changes** (not app bugs):
   - M5: the restore comparison has an Order lists row before Saved, so the check finds Saved by its label;
   - M8: the scan result has a third button, Add to order list (F21);
   - M10: Set up again now needs a failed Try again and DELETE typed (finding 1). The check does both and gained two checks (40 → 42).
5. **Check-script mistakes, fixed while writing the scripts:**
   - tab names read without a space before the count badge;
   - no camera in headless Chrome, so the typed code goes in the no-camera box;
   - the portrait screenshot showed an empty list, so the line controls weren't measured; it now opens a list with a line and checks for its three buttons;
   - the upgrade check waited for the Inventory screen while the app had reopened on Order;
   - it expected $8,413.66 after editing an item's count, and compared photos including thumbnails the list makes meanwhile.
6. **Not done here: the real tablet data.** `tests/tablet-backup.test.ts` needs the Tab S8 backup (below).
