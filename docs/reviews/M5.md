## Findings (all fixed in this review unless noted)

1. **"Later" didn't hide the banner on the screen it was tapped on** (browser check). The banner's clock ticks once a minute, so its `now` was older than the tap. A rule meant for a clock moved backwards treated that as "snooze expired". The rule was removed and a unit test added.
2. **"See the order list" in the price summary didn't navigate** (browser check). It was a link whose click also closed the dialog. It's now a button that closes the dialog and then opens Order.
3. **Dead check in the restore plan** (mutation check). `planRestore` re-validated items against a supplier list it had just completed from those same items, so it could never fail. It was removed. `replaceAll` still validates every item before writing.
4. **Two test gaps** (mutation check): a new vendor slot with a supplier but no pack size, and a file-name time like 10:75. Tests added; both mutants are now caught.
5. **Excel "CSV" files (Windows-1252)** would have turned × and ¾ into replacement characters. Restore and price import now fall back to Windows-1252 when a file isn't valid UTF-8, with a warning (test added).
6. **The storage-error screen** said restore "arrives in a later update". It now says the app has to be set up again before restoring, which arrives with first-launch setup (Q2, M10). **Open until M10:** a tablet whose database can't be opened still has no in-app way back.
7. **Open, minor:** Escape while the PIN stand-in is open over the restore dialog closes both. Nothing is changed (the gate answers "no"), but the restore dialog has to be reopened. This is the same dialog stacking as M3's delete; revisit with the real PIN pad in M6.
8. **Open, Stage 5:** on Android, whether Chrome shares the ZIP or saves it, whether `accept=".zip,.csv"` shows the files in the picker, and whether the share still has its user gesture after a ~1 s ZIP build.

## Decisions made while building (within the approved defaults)

- **A list file missing from a ZIP** (older backups, the starter catalog) keeps the tablet's list and adds missing names, the same as a CSV restore. Q5 covers ZIPs that have the file.
- **A backup with no items is refused**, rather than emptying the tablet.
- **Photo file extension follows the photo's type** (`.jpg`, `.png`, `.webp`), so a restored photo keeps its type. Starter and M7 photos are JPEG.
- **Price import:** a supplier spelled with different capitals uses the list's spelling. A new supplier is added only if it ends up on an item. Options whose values already match are counted as "already up to date", so a full data-only export works as the input. The PIN is asked after the file passes the check.
- **The PIN for restore is asked at Replace everything**, not before choosing the file, so the comparison can be read without a mentor.
- **Tablets that loaded the starter catalog before M5** get their setup time from the starter-load marker, so the reminder clock has a start (D7).

## Remaining uncertainty

- **Medium:** share vs. download, the file picker and `persist()` on the Tab S8 (Stage 5 list).
- **Low:** very large backups (hundreds of team photos) are built in memory. The starter catalog's 5.8 MB builds in about 1 s in desktop Chrome; the tablet is untested.
- The PIN is still the M3 stand-in (a confirmation). Until M6 is merged, anyone on the live site can restore or import prices by tapping Continue.
