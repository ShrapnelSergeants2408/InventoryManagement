## Details I filled in (confirmed by Dan 2026-11-13)

- (a) **+ New supplier…** takes a name only. Website and notes are added in More › Suppliers.
- (b) The supplier is added the moment **Add** is tapped, not when the item is saved, as with new locations. If the item is then cancelled the supplier stays in the list.
- (c) A conflict from two devices is only raised when the later count differs. A later count that matches is applied quietly.
- (d) An *older* count from the other device is still dropped as already applied, not raised, so a second device's early counts can be lost. This stays as in v0.18 to avoid false conflicts when a device re-sends its cumulative file after the other device has counted.
- (e) A conflict against an earlier import is raised only when the tablet already knows the kit has more than one device, and the item was counted since the kit was made.
- (f) The three choices are the existing ones, relabelled for this case.
- (g) The Backup screen and the Import screen show the newest import's Undo and say how many earlier ones follow.
- (h) Undo records are kept without limit until a restore or setup.
- (i) **Send all** includes every helper by default, including ones that already have a kit; sending makes a new kit for each (their progress restarts at 0).
- (j) If one helper's kit can't be built, nothing is shared for any of them.
- (k) **Counted n of m** counts only the helper's own counts (by name) dated after its last kit; counts made on this tablet don't count toward it, and a helper recount of an item someone else counted later does.
- (l) The kit file name has no date, so a re-sent kit has the same name. The kit inside still has its own kit id, so the phone and the import tell them apart.
- (m) Counts files keep `counts-<name>-<date>-<time>.zip`. Say if they should match the new style.
- (o) Reports and the spot-check list are for the newest import only; once a newer import is undone, the one before it becomes the newest and gets them back. They go with Undo: a restore or setup forgets them.
- (p) "Big change" uses fixed numbers (50% and 5 units), not settings. A conflict where the helper's number was not chosen (Keep this tablet's) is not in the report, because nothing changed for that item.
- (q) The report lists items the import changed (count, last-counted time or location), not rows that were skipped as already applied.
- (r) **B8 is the round date, not a copy of marks.** The kit's inventory already holds each item's last count and counter, so carrying the date is all it takes. A helper that was *not* in a round (tablet on "First count") gets "first count" too, as before. A kit from an older tablet has no date, so the helper starts on "first count".
- (s) **Recount after** is one setting for every item (not per category). An item counted exactly N days ago is not due; N+1 is.
- (t) An item never counted is not "due" (it is NOT COUNTED already), so before the first full count nothing is flagged.
- (u) The helper's recount age comes from the kit, so changing the setting on the tablet reaches a helper with its next kit.
- (v) Only Count and the status strip show it. There is no Inventory filter or sort for "due", and nothing on the item card. Say if you want either.
- (w) **C2 means setup needs a connection for the starter catalog and for "Start empty"** (it takes the 11 categories and 9 suppliers from that file). Restore works offline. A tablet that is set up offline, with no backup, can't start until it has a connection once.
- (x) **C1:** the workflow needs no secrets. Whether a failing check blocks merging is a GitHub branch-protection setting, not in the repo; say if you want it required.
- (y) The recount filter uses the same age as the chips (one age for all categories, as you decided).
- (z) **C4 moved only m25 to the shared start-up.** Rewriting the other 28 scripts is a large change with no new coverage, so they move over when they are next edited. The runner works with all of them as they are.
- (aa) **C5 leaves 6 advisories.** They need `vite-plugin-pwa` 1.1.0, an older release without Vite 8 support. They are in build-time packages (`workbox-build`), not in the shipped app.
- (n) A name with accents loses them (`Café` becomes `Cafe`); a name with no letters or digits is just `Helper.zip`.
