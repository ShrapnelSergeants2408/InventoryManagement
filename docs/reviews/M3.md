## Findings from reading the code

1. **Fixed (found by the browser check):** after saving an edit, Back showed the detail card a second time. The router now records which screen each history entry was opened from; Save goes back to the card when it came from there, and otherwise opens the card in place of the form. Either way, Back never reopens the form.
2. **Fixed (review, medium):** with the vendor fields locked, Save still re-read them from the form. The starter catalog round-trips exactly, but data restored in M5 could hold a link without `https://`, or a supplier in other capitals. That would normalize on save and count as a vendor change, so a student editing only the notes would be asked for the PIN or shown an error they can't fix. Locked vendor fields are now kept exactly as stored (`vendorsLocked`), with two tests and a mutant.
3. **Fixed:** a location could be named "No location", which looks the same as the group for items with no location. That name is now reserved (add, rename, and the editor's inline add).
4. **Fixed:** the enlarged photo closes with Escape too (as well as a tap anywhere or Close). Portrait: long titles truncate instead of pushing Save onto a second row; the lock icons sit inline in the note lines.
5. **Flag — until M6, medium:** every PIN step goes through `gate(reason)`. Until M6 a stand-in dialog answers it: it says why the PIN is needed and asks for a confirmation. Once M3 is merged, that's what the live site does, so anyone can confirm. Data is per tablet, and §6 says the PIN "prevents accidents, not determined tampering", so this is acceptable for a few milestones. The real PIN pad must replace the stand-in in M6, and the browser check's prompt counts become the M6 gate matrix.
6. **Accepted, noted:** buttons for things later milestones build are left out rather than shown dead: take/replace/remove photo (M7, the editor says so), Print QR label (M8), and Scan next to the barcode field (M8; the placeholder says so).
7. **Accepted, noted:** name and unit can be changed without the PIN. §6's "required" list doesn't include them, and mockup 3a shows them editable while the vendors are locked.
8. **Accepted, noted:** the supplier and location Rename dialogs also edit website and notes, behind the PIN. A notes-only change to a location therefore asks for the PIN; the spec is silent on notes.
9. **Accepted, noted:** removing a vendor option closes the gap (v3 becomes v2). The preferred vendor follows its option. Only the CSV column a vendor lands in changes.
10. **Accepted, noted:** renaming a category doesn't carry over whether its group was open on the Inventory list, so it shows collapsed once.
11. **Mockup vs data:** mockup 7a shows McMaster-Carr with 1 vendor option. In the starter catalog it has none (`other` has 1), so "Not used yet" is correct.
