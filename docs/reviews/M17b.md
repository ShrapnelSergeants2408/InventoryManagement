# M17b review — Aim and hold for camera scans (F21, F29; SPEC v0.10)

**Reviewed:** branch `m17b-scan-aim`. I read it as a review of someone else's work against:
- SPEC v0.10: F21 "Aim and hold", "Changes in v0.10", §20;
- Dan's report after the M17 tablet check: "the qr code reads so quickly that if several codes are close to each other it is not possible to focus on the correct one before the pop-up occurs". His answers: aim and hold, about 0.6 s, on every scanner.

**Date:** 2026-10-28 CDT

**Risk: Medium.** No data change, but every camera scan in the app now behaves differently. The camera used to take the **first code it found anywhere in the camera picture**, including the parts cropped off the screen, on the first frame that read.

## What was built

| Part | Where |
|---|---|
| **Where a code is on screen:** the camera picture is scaled to fill its box and the overflow is cropped equally (CSS `object-fit: cover`). A code's position in video pixels is mapped the same way. | `toView` in `src/domain/scan-aim.ts` |
| **Aim:** only a code whose center is inside the square (the screen's `.reticle`) counts; the nearest to its center wins. With no square, the visible picture is the area. A code the detector gives no position for counts only if it's alone. | `pickAimed` |
| **Hold:** the same code for `HOLD_MS` = 600 ms; a different code starts over; a missed frame of up to `HOLD_GAP_MS` = 400 ms keeps the hold. | `stepHold` |
| **Camera loop:** each frame (every 200 ms) measures the square and the camera box, picks the aimed code, steps the hold, and reports the code when ready. "The code just reported is ignored for 2.5 s" stays as it was, and those frames don't feed the hold. | `src/ui/components/Scanner.tsx` |
| **On screen:** while held, the square's corners turn amber and a bar fills along its bottom edge (`data-hold` and `--hold` set on the camera box directly, so the view doesn't re-render 5 times a second). Hints say "Hold … in the square". | `src/styles/scan.css`, `Scan.tsx`, `LocationScanDialog.tsx` |
| The detector's `boundingBox` is now part of `Detected` (native BarcodeDetector and the zxing stand-in both give it). | `src/io/barcode.ts` |
| **Spec v0.10.** | `docs/SPEC.md` |

## Findings while reviewing

1. **Fixed: the hold first showed one frame late.** The corners only turned amber from the second sighting, so the visible hold looked 0.4 s long. They now turn amber on the first frame and the bar fills from there.
2. **Earlier check updated for an intended change:** M8 expected the old Scan-tab hint "Point at a QR label or a barcode — it scans by itself"; it now reads "Hold a QR label or barcode in the square — it scans by itself".
3. **Note: a code larger than the square** (held very close) still counts, as long as its center is in the square.
4. **Note: count-in's "scan as you go" is about 0.6 s slower per item.** That's the cost of the hold; Dan chose it for every scanner.
