## Decisions made while building (for Dan)

1. **The search looks at the line as it's shown,** so it uses the preferred vendor's part # and supplier, not the other vendor options. This differs from the Inventory search (F4), which searches all options. On the order list, a match should be something you can see on the line.
2. **The note row comes before the column headers**, as F12 says ("a note in the file's first row"). Spreadsheets then show the note above the table. Anything that reads the file back as data would need to skip that row; nothing in the app does.
3. **The stale and no-price chips in the summary stay whole-list numbers** while searching. Only Lines, Total and Suppliers switch to "shown".

## Findings

1. **Fixed while building: a blank line after the note row.** `writeCsv` with no data rows ends in an extra line break. A unit test caught it, and the note row now ends with a single line break.
2. **Fixed while building: portrait footer.** "Total shown … · Grand total …" at heading size didn't fit a portrait line. The whole list's grand total moved into the smaller note line.
3. **The browser-check temp-folder cleanup (`bcf2a42`) is in this branch.** The same commit, `41cd5cc`, was pushed to the M13 branch after PR #17 had already been merged, so it never reached `main`. It's cherry-picked here.
4. **Check-script mistakes, fixed while writing the script (not app bugs):**
   - tile text read without a space between label and value;
   - expecting "neo" and "thrifty" to match only names and suppliers, when F12 also searches notes. The check now compares with matches worked out from IndexedDB.
