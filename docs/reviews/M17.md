# M17 review — Location QR codes (F29) and the app version line

**Reviewed:** branch `m17-location-scan`. I read it as a review of someone else's work against:
- SPEC v0.9: F29, the F21 and F25 additions, §20 (must-have tests), "Changes in v0.9";
- Dan's answers on 2026-10-28: the QR codes on the bins hold the location's name ("Electrical 15", "Tools 7"); scanning in the item editor, count-in, the Scan tab and More › Locations; an unknown code can be added as a location (anyone) or used to rename one (PIN); filtering reports "Location not found"; add the app version.

**Date:** 2026-10-28 CDT

**Risk: Low.** No schema, data-model or backup change; the new code calls the existing F25 add and rename. The one change to existing behavior: on the Scan tab, a code that isn't an item but could be a name (a QR code or typed text with a letter) now opens with "Location not found". Attach to an item and Add a new item are still offered below it.

## What was built

| Part | Where |
|---|---|
| **Matching:** the scanned text is trimmed and runs of spaces become one, and the inner spaces stay (unlike `cleanCode`, which removes them for barcodes). It matches a name ignoring capitals; otherwise it uses the single name that matches with spaces ignored ("Tools7"). A `2408:` team label is never a location. | `locationText`, `findLocation` in `src/domain/scan.ts` |
| **Which unknown codes offer Add and Rename:** a QR code or typed text that has a letter, isn't a web address or team label, and is at most 60 characters. Manufacturer barcodes never do. | `couldBeLocation` |
| **Scan resolution:** team label → item id → barcode → **location** → unknown. The unknown result also carries the spaced text. | `resolveScan(raw, items, locations)` |
| **One scan dialog**, used by four screens: camera with a square reticle; a "type it" box below; "Location not found" with Add, Rename (PIN, then pick the location), Scan again (`notFound="offer"`), or only Scan again (`"report"`). A team label gets a note instead. The Rename step closes if mentor tools relock. | `src/ui/components/LocationScanDialog.tsx` |
| **Item editor:** Scan beside the Location dropdown. | `Editor.tsx` |
| **Count-in:** a Scan chip in the walk's location picker (the location is saved with the count, as with the other picks). In "by location" mode, **Scan a location** on the start screen opens that location's walk. If the location has nothing to count it says so, and an unknown name is only reported. | `Count.tsx` |
| **Scan tab:** a location panel (name, item count, notes, the items; tap one for the usual found panel "In location Tools 7"; **Show in Inventory** sets the location filter alone and opens Inventory). "Location not found" offers Add, Rename (PIN; a panel to pick the location), attach, add item, and Scan again. | `Scan.tsx` |
| **More › Locations:** **Add by scan**. A name already in the list says so. | `Locations.tsx` |
| **Filters panel:** Scan a location in the Location section. A known location with items sets the filter; one with no items says so; an unknown name is only reported. | `FilterPanel.tsx` |
| **App version:** More › About › "App version 0.4.0 · Built Oct 28, 2026, 12:20 PM" (the build time comes from Vite's `define`). `APP_VERSION` 0.3.0 → 0.4.0 (also written into backups' `manifest.json` and kits). | `More.tsx`, `vite.config.ts`, `src/build-info.d.ts`, `src/io/backup.ts` |
| **Spec v0.9:** F29, the F21 and F25 pointers, "Changes in v0.9", decision log, §20 tests. | `docs/SPEC.md` |

There's no mockup for these screens. They reuse the Scan panels, the barcode Scan dialog and the existing buttons.

## Findings while reviewing

1. **Fixed: the Scan tab's Attach → Back lost the space.** Going back rebuilt the result from the barcode form of the code ("Tools7"). The attach panel now keeps the result it came from.
2. **Fixed: the dialog and the Scan tab used different icons** for "Location not found" (question mark vs pin). Both use the pin now.
3. **Note: a typed id that doesn't exist** (e.g. `st-9999`) now opens as "Location not found", since it has letters. Attach and Add item are still there, so nothing is lost, but the heading is less apt than "Not in the inventory yet". Left as is: telling an item-id-like text from a bin name would be guessing.
4. **Earlier checks updated for intended changes:** M16a expected app version `0.3.0` in the kit (now `0.4.0`); M8 clicked the editor's first Scan button, which is now the Location one (it now clicks the barcode field's); M9's location chips now end with Scan.
5. **Not a code change: first-pass flakes** in M9 (setup) and M12 (navigation) are noted above. Both passed on re-run.
