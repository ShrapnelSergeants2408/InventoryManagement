## Findings in this review (fixed)

1. **Pause could be tapped while a save was running.** The save would then carry on to the next item and override the pause. Pause is now off during a save (milliseconds on the tablet, so this was unlikely, but cheap to rule out).
2. **Test gap: the summary's Short count wasn't checked against a low-spares item.** Counting low spares as short went unnoticed. The test now has a low-spares item.
3. **The scanner's amber line was drawn as a block** (an M8 bug, found here in the count-in screenshot). The order list's `.line` class (`min-height: 68px`, padding) also matched the reticle's line, on Scan, in the editor's scan dialog and in count-in. Reset in `scan.css`; the M8 and M9 checks now measure the line (3 px).
4. **In scan mode, the label still in front of the camera reopened the item just saved** after the 2.5 s repeat window. The camera now ignores the item just saved or skipped until another item is saved or skipped; typing its code still opens it. Found before the first commit; the browser check waits 3.5 s and expects no reopen.
5. **In scan mode the camera restarted for every item**, because it sat inside the per-item part of the screen. Moved outside it; the browser check confirms the camera stays live from one item to the next. Found before the first commit.
6. **The scanner stopped after its first report** (an M8 bug, found by an interface mutant that this review's browser check missed at first). `Scanner` stopped scanning after each code until it was paused and resumed. The Scan tab always pauses while a result is shown, so it never noticed, but count-in never pauses: after the first camera scan, no other label would ever be read. It now keeps scanning; the 2.5 s repeat window still stops a label from being reported over and over. The M9 check now has the camera read the same label a second time after another item, and checks that a label still in view doesn't take over an item that was just typed. M8 re-run: 61/61 on 2 runs.

## Decisions made while building (within the spec)

- **A walk is fixed when it starts.** Picking a location for an item during a by-location walk doesn't reshuffle the walk; the item stays in it and in its summary.
- **Continue opens at the first item not counted yet; Recount opens at item 1.** The group's whole list stays reachable with Back.
- **The pause point** (mode, group, item) is kept in this tablet's local storage, like filters and the label layout; the counts themselves are in IndexedDB. It's cleared when a walk reaches its summary.
- **Location quick picks** are the 5 most recently used locations (F25), plus the item's own location. The "All locations…" list appears when there are more locations than quick picks.
- **A location is saved only with Save**, never with Skip.
- **Keypad limit:** 5 digits (99,999).
- **Scan as you go:** a typed count isn't lost when another label comes into view; the screen asks to save or skip first. Pause shows how many items were counted while scanning. Unknown barcodes point to the Scan tab, which has attach and add (F21).
- **The summary's Short tile** counts items saved in this walk that are short now (as in the mockup); Counted is out of the whole group.
- **"Recommended for the first count"** shows on By category only while nothing has been counted.
- The last placeholder screen is gone, so `Placeholder.tsx` was removed.

## Open items

- **For Dan (low): recounts have no "round".** `last_counted` (F24, D8) says whether an item was ever counted, so after the first full count every group shows Recount and 100%, and a second inventory count can't show its own progress. Within the spec as written. If you want per-round progress later, one option is "counted since <date>" on the start screen, using the dates already stored. No change made.
- **Stage 5 (Tab S8):** a real count with gloves (key size, speed), the native `BarcodeDetector` reading labels at arm's length, and the camera staying on through a long scan session (battery, heat).
