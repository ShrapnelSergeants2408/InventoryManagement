## Details I filled in (Dan to confirm or change)

- **(a) Repeats:** within one import, a row that's exactly the same as one in an earlier file (same helper, item, time and values) is counted as already applied. That's what cumulative files produce.
- **(b) The same helper's older count** (counted_at earlier than this tablet's count by that helper) is skipped as already applied, so an older file imported after a newer one can't undo it.
- **(c) A different location or barcode defaults to Keep this tablet's**, and doesn't hold up Apply. Only count conflicts must be chosen (as §18.5 says for Apply).
- **(d) A barcode another item already has** is not used; it's listed under Skipped.
- **(e) An unknown kit:** with no kit time to compare, a different number is a conflict unless this tablet never counted the item or the same helper did.
- **(f) Add together** takes the newer of the two count times, and counted_by becomes the helper's name.
- **(g) A new location name chosen as Add** is created even if no item ends up there (the helper created it; `locations-new.csv` lists it).
- **(h) Only the last import can be undone.** Undo puts the five fields back even if an item was counted again after the import (that later count is undone too). It also puts back the helpers' "last import" time.
- **(i) Decided pending items are remembered** (accepted, matched, combined away or discarded), so importing the same file again never brings them back. A full restore of an older backup can bring back pending items it holds.
- **(j) Accept doesn't fill in a supplier** when the helper gave none; the student chooses one, as when adding any item.
