## Decisions made while building (for Dan)

1. **"Select all shown" with no search or filter selects every item**, collapsed groups included, since they're all "shown" in the list's count. The button shows the number, e.g. (129).
2. **The selection survives a search or filter change.** Items picked earlier stay picked and are counted as "not shown" in the bar. The Move confirmation still lists where every item comes from.
3. **Select mode hides the On-hand stepper,** so a tap meant for a checkbox can't change a count. Done brings the steppers back.
4. **After a move, Select mode ends** and the selection is cleared. A toast says what happened.
5. **A typed new name matching an existing one** (ignoring capitals) uses that category or subcategory instead of refusing, as the item editor does.

## Finding 3: the test machine's drive is full (environment, not the app)

During the regression, C: had 2 GB free of 237 GB, and 32 Chrome processes were running. Every browser check starts headless Chrome with a new temporary profile (`mkdtemp(join(tmpdir(), 'cdp-'))`) and never deletes it. Stage 4–6 runs have left these behind in `%TEMP%`. A Chrome that can't write its profile fails IndexedDB with "UnknownError", which is what M7 hit. Suggested follow-up: have the check scripts delete their profile and close Chrome in `finally`, and clear the old `cdp-*` folders (Dan to decide).
