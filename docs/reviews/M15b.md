## Decisions made while building (for Dan)

1. **Select sits at the end of the Order tab row** (not in the top bar, which already holds search and two export buttons and would overflow while searching). It shows on the Automatic list only.
2. **In Select mode, tapping an item's name ticks it** instead of opening its detail card, as in Inventory Select mode.
3. **The rule and the list are remembered** until the app is reloaded. The first time, the rule is "up to desired + spares", matching the automatic list.
4. **Quantities are stored as whole packs** (the rule's order quantity), so the list shows exactly what will be bought.
5. **After adding, the app opens the list**, so you see the result straight away.
6. **Inventory selections can include items that don't need ordering.** "Up to desired" skips them (counted in the dialog); "One pack each" adds them.

## Findings

1. **Fixed while building: a misleading button.** Before Replace or Keep was picked, the dialog's button read "Nothing to add" even when Replace would change 45 lines. It now reads "Choose replace or keep" until a choice is made. Found in the screenshots.
2. **The M15 check updated for an intended change:** the tab row on the Automatic list now ends with Select, so the M15 and upgrade checks read the list tabs only (`.ltab:not(.sel)`).
3. **Check-script mistake, fixed while writing:** the Inventory step's "Keep" check first only tested that the list grew. It now compares the exact lines with the F4 search worked out here.
