## Findings from reading the code

1. **Fixed:** a typed number followed immediately by Enter or a blur could be read from the stale draft state, so the save was skipped. The stepper now reads the box's value directly. Found by the browser check.
2. **Fixed:** SPEC §17 says text ≥ 15 px, but the mockup's column labels were 12 px. The spec wins. The layout still fits at 1280 × 800 and 800 × 1280 (screenshots 03 and 07).
3. **Fixed:** Escape, or a rejected typed value, left the typed text on screen, because Preact skips the DOM update when the value prop hasn't changed. The box is now reset directly. A failed save also restores the old number and shows a toast.
4. **Fixed:** the temporary starter-catalog auto-load (until M10) ran whenever the tablet had 0 items. After M3 adds delete, removing every item would have brought the catalog back. It now runs once (`starterLoadedAt` marker).
5. **Accepted, noted:** list rows keep starter-catalog order (by id), not A–Z. The catalog order is meaningful (screw lengths ascending), and A–Z would sort "10-32 x 1 in." before "3/8 in.". Team-added items (`tm-…`) appear after starter items in their group.
6. **Accepted, noted:** the search text isn't remembered across reloads (filters and open groups are). A stale search on reopening would hide items unexpectedly.
7. **Accepted, noted:** thumbnails (160 px JPEG) are made the first time a row shows, one at a time, and stored in the photo record. They aren't part of backups. This avoids decoding 128 full-size photos at once on the tablet. M7 will make them on save and import.
8. **For M10 — flag, medium:** Pages is served from the org's custom domain, **`https://team2408.com/InventoryManagement/`** (`shrapnelsergeants2408.github.io/InventoryManagement/` redirects there). The app's IndexedDB and localStorage therefore share an origin with anything else on team2408.com. Keys and the database name are prefixed (`frc2408…`). The service worker must be scoped to `/InventoryManagement/`. And if the domain or path ever changes, the tablet's data stays behind at the old origin, so restoring from a backup is the way to move it. (The domain isn't set in this repo.)
